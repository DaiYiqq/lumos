# Translation Guide

Lumos currently ships **four READMEs** and a **Chinese/English UI**. This guide explains how to keep
existing translations in sync and how to add a new language end to end. Translation contributions do
not require Rust knowledge.

- README languages: 简体中文（默认）, English, 繁體中文, 日本語
- UI languages: 中文 / English (Settings → Language)

## Repository layout

| Path                | Purpose                                                             |
| ------------------- | ------------------------------------------------------------------- |
| `README.md`         | Simplified Chinese README (default, source of truth)                |
| `README.en.md`      | English README                                                      |
| `README.zh-TW.md`   | Traditional Chinese README                                          |
| `README.ja.md`      | Japanese README                                                     |
| `src/i18n/index.ts` | UI dictionary: Chinese source string → English, plus language store |
| `docs/I18N.md`      | This guide                                                          |

## Translating the UI

UI strings use the **Chinese text as the dictionary key** to keep component code small:

```ts
// src/i18n/index.ts
const ENGLISH: Record<string, string> = {
  设置: "Settings",
  "已就绪：{model}（{dim} 维）": "Ready: {model} ({dim} dims)",
};
```

Rules:

1. Add a new entry to the dictionary; `{name}` style placeholders are interpolated by `translate()`.
2. In components, use the hook:

   ```tsx
   const t = useT();
   return <h1>{t("设置")}</h1>;
   ```

3. Never hard-code new user-facing text in JSX. Backend error strings are runtime data; translate
   only stable UI copy.
4. Run `pnpm typecheck && pnpm lint && pnpm test`. The test `可以在设置页切换中英文界面` must pass.
5. Check for missing translations: switch to English in Settings, then walk through Libraries, Chat,
   Settings and dialogs. Any Chinese copy that is not user data (library names, documents) should be
   translated.

### Adding a new UI language (e.g. Japanese)

The current store supports `"zh" | "en"`. To add a language:

1. Extend `Language` in `src/i18n/index.ts` and add a dictionary (e.g. `const JAPANESE: Record<string,
string> = { "设置": "設定", ... }`) with entries for every key in `ENGLISH`.
2. Update `translate()` to select the dictionary by language, and `readLanguage()` to accept the new
   locale code (e.g. `ja`) from `localStorage`.
3. Add a button in **Settings → Language** (`src/components/settings/SettingsView.tsx`).
4. Update `src/App.test.tsx` with a switching test for the new language.
5. Run the quality gates and include a screenshot of the language in the PR.
6. Add the README translation (see below) and update the language table in this document and in the
   READMEs.

> Tip: keep the English dictionary as the fallback. A missing key should fall back to the Chinese
> source rather than crash.

## Translating the README

1. Copy `README.md` (Simplified Chinese, default) to `README.<bcp47>.md` (e.g. `README.ko.md`,
   `README.es.md`).
2. Keep the structure: language switcher, download table, per-platform install steps, features, usage,
   architecture, retrieval benchmark, privacy, roadmap, docs, contributing, developer contacts, license.
3. **Keep every link, file name and version number identical.** The download table must point to the
   same `releases/download/vX.Y.Z/<asset>` files.
4. Add the new README to the language switcher in **all** README files.
5. Update the language list in `README.md`, this file, and the release workflow body
   (`.github/workflows/release.yml`).
6. Screenshots are language-neutral; no need to duplicate images.

## Glossary

Keep these terms consistent across languages:

| English                  | 简体中文             | 繁體中文             | 日本語                   |
| ------------------------ | -------------------- | -------------------- | ------------------------ |
| knowledge base / library | 知识库               | 知識庫               | ナレッジベース           |
| document                 | 文档                 | 文件                 | 文書                     |
| chunk                    | 分块                 | 切塊                 | チャンク                 |
| citation                 | 引用                 | 引用                 | 引用                     |
| embedding                | 嵌入 / 向量          | 嵌入 / 向量          | 埋め込み                 |
| retrieval                | 检索                 | 檢索                 | 検索                     |
| conversation             | 会话 / 对话          | 工作階段 / 對話      | 会話                     |
| provider                 | Provider（模型服务） | Provider（模型服務） | Provider（プロバイダー） |
| offline mode             | 离线模式             | 離線模式             | オフラインモード         |
| local-first              | 本地优先             | 本地優先             | ローカルファースト       |

If you start a new translation, open an issue with the `translation` label and mention the language.
We will add you to [MAINTAINERS.md](../MAINTAINERS.md) as a translation maintainer once the first PR
is merged.

## Review checklist for translation PRs

- [ ] No missing sections compared to `README.md`
- [ ] Language switcher updated in every README
- [ ] Download links and version numbers unchanged
- [ ] Code blocks and commands unchanged
- [ ] UI dictionary keys match exactly (including placeholders)
- [ ] `pnpm typecheck`, `pnpm lint`, `pnpm test` pass
- [ ] Screenshot attached when UI text changes
